How restoring works

Restoring creates a new commit based on the selected revision and triggers a new deployment. Git history is kept, but newer site changes can be replaced. A saved commit is not necessarily a verified working deployment. Make a backup before restoring an older revision.

GITHUB AUTHORIZATION

GitHub access token

A token allows an authorized maintainer to publish updates. Create a replacement when one expires or is revoked.

The stored token was rejected by GitHub. It may be expired, revoked, or invalid. Create a new one and reconnect.
  1. Create a fine-grained token. Open GitHub's token settings and select the repository owner.
  2. Restrict access. Choose filmmicfoundations.github.io only.
  3. Set permissions. Contents → Read and write; Actions → Read-only for deployment history.
  4. Set an expiration. Choose a short lifetime, generate the token, and paste it into GitHub access on the Updates tab.

The token is stored in this tab's session storage for convenience, not in local storage or the repository. It normally clears when the tab closes; some browsers may restore tab sessions. Disconnect or Lock clears it immediately. This public-page approach is less secure than server-side authentication.
